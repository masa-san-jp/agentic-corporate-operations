# Glossary

| 用語 | 定義 |
|---|---|
| Work Object | 業務を一意に識別し、目的、状態、期限、入力、出力、責任、権限、完了条件、証跡を保持する共通データ単位。 |
| Decision Object | 経営・業務上の意思決定を、論点、選択肢、根拠、権限、決定、レビュー条件とともに保持するデータ単位。 |
| Policy | 法令、規程、契約、権限、予算、禁止事項、判断原則を機械判定可能に表した制約。 |
| Protocol | 複数の主体が特定目的を達成するための状態遷移、メッセージ、入力、出力、失敗時動作の規約。 |
| SOP | 特定業務を再現可能に実行するための標準作業手順。 |
| Agent | 目的、権限、入力、出力、ツール、制約、評価方法を与えられ、業務を遂行する実行主体。 |
| Orchestrator | Work Objectを分解し、複数のエージェント、ツール、人間、外部組織へ配分して進行を管理する機構。 |
| Task Curator | 曖昧な入力を分類、正規化、分解し、完了条件と次の行動を持つWork Objectへ変換する機構。 |
| Policy Engine | 事実とPolicyを照合し、義務、禁止、裁量、必要承認を判定する機構。 |
| Evidence | 入力、判断、実行、承認、検証、外部応答、成果物を再現・監査するための記録。 |
| Evidence Engine | Evidenceを収集、関連付け、改ざん防止、保持、検索する機構。 |
| Validator | 出力が構文、意味、業務、Policy、完了条件を満たすか独立評価する主体。 |
| Exception | 正常な状態遷移を継続できない、原因と収束条件を持つ構造化された状態。 |
| Exception Manager | 再試行、代替、再分解、督促、エスカレーション、中止を選択し、Exceptionを収束させる機構。 |
| Escalation | AIが処理できない価値判断、権限行使、未知の例外を、判断材料付きで人間または上位主体へ移すこと。 |
| Acceptance Criteria | 成果物または業務を完了と判定するための機械検証可能な条件。 |
| Autonomy Level | 人間とAIの関与割合をA0からA5で表す区分。 |
| Risk Class | 金銭、法務、個人、対外、機密、不可逆性、検出困難性、継続性への影響に基づく区分。 |
| Control | リスクを予防、発見、是正する仕組み。 |
| Continuous Control Monitoring | 統制の存在と有効性を継続的またはイベント駆動で検査する仕組み。 |
| Human-in-the-loop | AIの処理途中に人間の判断または承認を必須とする設計。 |
| Human-on-the-loop | AIが自律実行し、人間が監督・事後確認・停止権限を持つ設計。 |
| Human-over-the-loop | 人間が目的、Policy、権限、リスク許容度、システム変更を統治する設計。 |
| RTO | 障害発生後、業務を復旧させるまでの目標時間。 |
| RPO | 障害時に許容されるデータ損失時点の目標。 |
| ADR | 重要なアーキテクチャ上の意思決定と理由を保存する記録。 |

## 用語運用規則

- 同一概念に複数の日本語訳を使用しない。
- 新規用語は使用前に本書へ追加する。
- 業務領域固有の用語は、共通用語との関係を明記する。
- 「対応中」「確認中」「保留」など、退出条件のない状態名を使用しない。
